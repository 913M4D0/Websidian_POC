# AI 사용 고지와 책임 경계

## 개발 과정의 AI 사용

Websidian의 아이디어 정리, 자료 조사, UI 설계, 코드 작성, 테스트와 문서화 과정에는 ChatGPT·Codex 계열 생성형 AI가 보조 도구로 사용됐다. AI가 제안한 내용은 자동으로 회사 정책이나 업무 결론이 되지 않으며, 기능 범위의 선택, 실행, 수정, 검증과 공개 책임은 프로젝트 작성자에게 있다.

공개된 코드가 AI의 정확성, 독창성, 보안성 또는 제3자 권리 비침해를 보증하지 않는다. 제출·배포 전에는 사람이 코드, 생성 문구, 의존성 및 출처를 검토해야 한다.

## 실행 중 사용되는 AI

외부 AI는 서버 설정이 존재하고 사용자가 해당 기능을 실행한 경우에만 호출된다.

| 기능             | 경로                        | 현재 요청 모델            | 전송되는 주요 정보                                            |
| ---------------- | --------------------------- | ------------------------- | ------------------------------------------------------------- |
| 이슈 분석        | OpenRouter Chat Completions | `openai/gpt-5.6-luna`     | 선택 이슈와 서버가 수집한 접근 가능한 완료 이력의 제한된 발췌 |
| 테스트 케이스    | OpenRouter Chat Completions | `openai/gpt-5.6-luna`     | 위와 동일한 근거 문맥                                         |
| 파생 기억 컴파일 | OpenRouter Chat Completions | `openai/gpt-5.6-luna`     | 완료된 단일 이슈의 원문·활동·처리 정보                        |
| 의미 색인        | OpenRouter Embeddings       | `qwen/qwen3-embedding-8b` | 사용자가 명시적으로 색인한 완료 이슈의 검색용 발췌            |

모델 ID는 서버 설정 및 OpenRouter의 공개 모델 목록과 일치할 때만 사용한다. 코드의 `allow_fallbacks`는 같은 모델을 제공하는 OpenRouter 내부 제공자 라우팅을 허용할 수 있지만, 애플리케이션이 임의의 다른 모델 ID를 선택한다는 뜻은 아니다. 실제 제공자, 이용 가능성, 가격, 처리 위치와 정책은 호출 시점의 OpenRouter 및 하위 제공자 조건에 영향을 받는다.

현재 코드 정책은 Luna의 `max` 추론을 요구하고, 분석·테스트 케이스·파생 기억 모두 16,000토큰·180초를 요청 상한으로 둔다. `max` 지원을 확인하지 못하면 더 낮은 추론 강도로 묵시적 대체하지 않는다. 실제 허용량과 과금량은 모델·제공자 응답 및 배포 설정에 따라 더 작거나 달라질 수 있으며, 코드 변경 후에는 `lib/llm-policy.ts`를 기준으로 다시 확인해야 한다.

이슈 분석은 연결된 원문을 원인 후보·위험·처리 방향의 읽기 쉬운 초안으로 정리한다. 테스트 케이스는 개발자가 자기 구현의 정상 경로에 집중할 때 놓치기 쉬운 과거 재시도·롤백·경계값·공유 모듈·타팀 변경의 회귀 조건을 검증 후보로 바꾸는 데 목적이 있다. 두 기능 모두 원문 근거를 대체하지 않으며, 생성된 테스트의 실행 가능성과 커버리지는 사람이 검토한다.

## 데이터 처리 요청

- 생성 요청은 OpenRouter 제공자 설정에 `data_collection: deny`를 전달한다.
- 임베딩 요청은 이에 더해 `zdr: true`와 OpenRouter 캐시 비활성화를 요청한다.
- 위 플래그는 애플리케이션이 요청하는 라우팅·처리 조건이다. 조직의 보안 승인, 법적 계약, 데이터 처리계약 또는 모든 하위 제공자의 준수를 Websidian이 독립적으로 보증하지 않는다.
- OpenRouter 키는 서버 비밀로만 설정하고 소스, 브라우저, 로그, 문서 또는 채팅에 넣지 않는다.
- 개인정보, 고객정보, 영업기밀, 운영 인증정보 또는 외부 제공이 승인되지 않은 자료를 POC에 입력하거나 AI 기능으로 전송해서는 안 된다.

## AI가 하지 않는 일

- AI 분석·테스트·파생 기억은 원본 이슈의 제목, 본문과 처리 이력을 수정하지 않는다.
- AI는 이슈를 자동으로 완료하거나 GitHub 이슈의 상태를 변경하지 않는다.
- GitHub 가져오기는 REST 기반 단방향 스냅샷이며 AI 기능이 아니다.
- Sites는 POC의 호스팅·인증 게이트웨이와 D1 바인딩을 제공하는 실행 환경이며, 이슈 분석 모델이 아니다.
- 그래프 배치, 원문 검색, 권한 범위, 입력 검증, 멱등 생성과 revision 충돌 처리는 결정론적 애플리케이션 로직이다.

## 결과의 한계와 책임

AI 출력은 누락, 잘못된 연결, 과도한 일반화 또는 사실과 다른 문장을 포함할 수 있다. 시스템은 모델이 인용한 이슈 ID가 제공된 근거 목록에 포함되는지 검사하지만, 이 검사가 인용 내용의 진실성이나 인과관계를 보증하지는 않는다.

분석과 테스트 결과는 검토를 돕는 초안이다. 업무 처리, 배포, 테스트 범위, 리스크 수용과 규제 준수에 대한 최종 판단은 권한 있는 사람이 원문 근거를 확인한 뒤 내려야 한다. 외부 AI가 실패하면 분석·테스트는 원문 기반 결과로 대체될 수 있고, 완료 이슈의 canonical 기록은 AI 없이도 유지된다.

## 호출 측정 로그

분석·테스트·파생 기억·임베딩 호출은 모델·프롬프트 버전·근거 수·입력 문자수·첫 출력 시간·총시간·토큰·재시도·상태를 내용과 분리해 기록한다. 프롬프트, 이슈 원문, 생성 결과와 API 키는 측정 테이블에 저장하지 않으며 인증 소유자 키는 일방향 SHA-256 범위값으로 저장한다. 이슈 ID는 합성 POC의 호출을 연결하기 위해 보존한다.

Chat Completions 비용은 제공자 응답에 값이 있을 때만 OpenRouter credit 단위의 백만분율 정수로 기록한다. 임베딩 응답은 비용을 반환하지 않을 수 있으므로 비용이 비어 있는 행을 0원으로 해석하거나 전체 AI 비용으로 합산해서는 안 된다. 실제 제공자 비용은 OpenRouter 사용 내역과 대조해야 한다.

## 공개 소스와 라이선스

현재 저장소에는 `LICENSE`가 없다. 작성자·회사·제3자 간 권리 귀속과 의존성 조건을 확인하기 전 임의의 오픈소스 라이선스를 부여하지 않기 위해서다. 공개 저장소라는 이유만으로 코드나 합성 데이터를 자유롭게 사용·수정·배포할 수 있다고 해석해서는 안 된다. 향후 라이선스를 추가할 때는 AI 보조 산출물, 직접 작성 코드, 외부 참고물과 패키지 라이선스를 함께 검토해야 한다.
