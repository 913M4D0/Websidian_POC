# 보안·개인정보 및 외부 서비스 경계

## 현재 보안 상태

Websidian은 합성 데이터로 기능을 시연하는 개인 POC다. 회사의 보안 검토를 통과한 운영 서비스, 규제 데이터 처리 시스템 또는 전사 협업 플랫폼이 아니다. 실제 회사 데이터, 개인정보, 고객정보, 금융정보, 영업기밀과 운영 인증정보를 입력하는 용도로 승인되지 않았다.

## 데이터와 외부 서비스의 흐름

| 구성요소   | 역할과 데이터 흐름                                                  | 경계                                                                                |
| ---------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Sites      | 호스팅, 로그인 게이트웨이, 사용자 식별 헤더와 D1 바인딩 제공        | AI 모델이 아니며 배포 공개 범위와 계정 접근은 별도 설정이다                         |
| D1         | 사용자별 이슈 overlay, 파생 기억·벡터, AI 호출 제한과 내용 없는 측정 로그 저장 | POC 저장소이며 운영용 보존·백업·삭제 정책은 아직 없다                     |
| GitHub     | 사용자가 지정한 저장소의 이슈·댓글을 서버가 읽어 단방향 스냅샷 생성 | 원본 GitHub를 수정하지 않으며 저장소 접근권한과 콘텐츠 사용권한은 사용자가 확인한다 |
| OpenRouter | 분석·테스트·파생 기억·임베딩 요청을 외부 모델 제공자에게 중계       | 입력 문맥이 외부 서비스로 전송되며 해당 제공자 정책과 계약이 적용된다               |

GitHub에서 가져온 콘텐츠도 사용자가 분석·테스트·기억·의미 색인을 실행하면 관련 문맥의 일부가 OpenRouter로 전송될 수 있다. 공개 저장소라는 사실이 외부 AI 처리 허가를 자동으로 의미하지 않는다.

## 현재 구현된 방어선

- Sites 게이트웨이가 주입·덮어쓰는 `oai-authenticated-user-id`를 사용자 식별자로 사용한다.
- 이슈와 파생 기억은 사용자 ID 범위로 조회·저장한다.
- 변경 API는 같은 origin의 JSON 요청을 요구한다.
- 생성 요청의 멱등성, revision 기반 동시 변경 거부, 입력 길이·크기 제한과 AI 호출 제한을 적용한다.
- 서버가 접근 가능한 완료 이력만 다시 수집하며, 클라이언트가 임의의 모델·시스템 프롬프트·근거 원문을 직접 지정하지 않는다.
- 이슈 원문과 외부 콘텐츠를 비신뢰 데이터로 취급하고 그 안의 지시를 실행하지 않도록 모델에 명시한다.
- 모델 인용 ID와 평문 구획을 검증하며, 불완전한 결과는 원문 기반 경로로 대체한다.
- canonical 이슈와 AI 파생 데이터를 분리하고, 임베딩 벡터와 파생 요약을 일반 이슈 응답으로 브라우저에 보내지 않는다.
- API 응답에는 private·no-store 캐시 정책을 적용한다.
- GitHub 토큰과 OpenRouter 키는 선택적 서버 비밀이며 브라우저 입력이나 API 응답에 포함하지 않는다.
- AI 측정 로그에는 원문·프롬프트·생성 결과를 저장하지 않고 인증 소유자 키를 SHA-256 범위값으로 저장한다. 합성 POC의 호출 연결을 위해 이슈 ID, 모델 ID, 사용량, 시간, 상태는 보존되며 현재 자동 삭제 정책은 없다.
- 생성과 임베딩 호출 모두 D1의 사용자별·기능별 요청 한도를 공유한다. 같은 종류의 임베딩 요청은 동일 Worker 실행 인스턴스에서 한 번에 하나만 처리하며, 인스턴스 간 전역 중복 차단은 운영 전 D1 원자 잠금이나 멱등 키로 보강해야 한다.

이 방어선은 POC 수준의 구현 사실이며 완전한 보안 또는 규제 준수를 보증하지 않는다.

## 운영 전 필요한 항목

실제 조직 데이터나 다수 사용자를 다루기 전에 최소한 다음 항목이 필요하다.

- 회사 SSO와 조직·팀 기반 RBAC
- 이슈·자료별 ACL과 외부 커넥터 권한 전파
- 관리자 감사로그, 사용자 활동 추적과 변경 불변성 정책
- 데이터 분류, DLP, 개인정보·비밀정보 탐지와 마스킹
- 보존·삭제·백업·복구 및 퇴직·권한 변경 처리
- 비밀 키 발급·회전·폐기, 비용 한도와 비정상 사용 탐지
- OpenRouter·하위 모델 제공자·Sites·D1·GitHub에 대한 보안·법무·구매 검토
- 데이터 처리 위치, 보존 여부, 재학습 여부와 사고 통지 조건 확인
- 프롬프트 인젝션, 잘못된 인용, 데이터 유출과 권한 우회에 대한 적대적 테스트
- 장애 대응, 공급자 중단 시 원문 기반 모드 전환과 운영 복구 절차
- 모델·프롬프트·색인 버전 관리와 품질 회귀 평가

현재 코드는 Sites 게이트웨이가 인증 헤더를 안전하게 주입한다는 전제에 의존한다. 이 헤더를 신뢰할 수 없는 별도 Worker 주소나 우회 origin으로 애플리케이션을 노출해서는 안 된다.

## 안전한 공개 데모 원칙

1. 배포 데이터는 합성 이슈만 사용한다.
2. `.env`류 파일, API 키, 토큰, 쿠키와 내부 URL을 저장소·ZIP·영상에서 제거한다.
3. Git 전체 이력과 빌드 산출물에도 비밀정보가 남지 않았는지 확인한다.
4. 실제 회사명·개인명·고객명·계좌·거래·장애·서버·파일 경로를 사용하지 않는다.
5. GitHub 가져오기는 권한과 공개 가능성을 확인한 별도 데모 저장소에만 실행한다.
6. 외부 AI 호출 화면에는 합성 데이터임을 표시하고, 생성 결과를 사실이나 업무 결론으로 단정하지 않는다.
7. 공개 링크의 접근 범위와 종료 시점을 정하고, 시연 후 불필요한 비밀 키와 데이터를 폐기한다.

## 공개 코드의 권리 상태

`LICENSE`는 권리 귀속과 제3자 조건 확인 전까지 추가하지 않는다. 현재의 공개는 심사·검토와 재현 가능성을 높이기 위한 소스 열람이며, 별도의 사용·수정·재배포 허락이 아니다. 패키지와 외부 서비스는 각 제공자의 라이선스·약관을 별도로 따른다.
