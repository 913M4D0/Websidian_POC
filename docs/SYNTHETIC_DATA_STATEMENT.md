# 합성 데이터 및 정량값 고지

## 요약

Websidian은 실제 업무와 유사한 이슈 관리·히스토리 탐색 흐름을 검증하기 위한 개인 POC다. 저장소에 포함된 기본 이슈와 공개 시연 데이터는 합성 데이터이며, 회사의 실제 사건이나 운영 기록이 아니다.

## 기본 데이터의 범위

- `data/issues.json`의 이슈 294건은 모두 합성 데이터다.
- 구성은 대표 시나리오 24건과 일반 시각화·탐색용 270건이다.
- 이슈 ID, 제목, 본문, 날짜, 담당 팀, 분류, 활동, 처리 결과, 관련 자료 식별자와 이슈 간 관계는 POC를 위해 작성한 가상 정보다.
- `code:/`, `doc:/`, `policy:/` 등 자료 표기는 검색과 관계 계산을 시험하기 위한 합성 식별자다. 실제 사내 파일, 저장소 경로, 커밋 또는 문서를 가리키지 않는다.
- `data/github-issue-drafts.json`과 `data/github-bindings.json`이 가리키는 대표 GitHub 이슈 24건도 같은 합성 시나리오의 공개 사본이다. 열린 상태와 닫힌 상태는 시연 흐름을 위한 설정이며 실제 장애·개선 이력이 아니다.
- 특정 회사·조직·업무에서 흔히 볼 수 있는 표현이 등장하더라도 실재 인물, 고객, 시스템, 거래, 장애 또는 의사결정과의 일치는 의도하지 않았다.

## 이 고지가 적용되지 않는 데이터

애플리케이션 실행 후 사용자가 직접 만든 이슈와 사용자가 GitHub 가져오기로 불러온 외부 이슈는 배포된 합성 seed와 별개의 사용자 입력이다. Websidian은 외부 저장소 내용의 합성 여부나 공개 가능성을 판정하지 않는다. 입력·가져오기 권한과 내용의 적법성, 보안 등급, 외부 AI 전송 가능 여부는 해당 사용자가 확인해야 한다.

## 사용할 수 있는 목적

합성 데이터는 다음 항목을 검증하기 위해 제공한다.

- 294개 노드의 목록·검색·성운 시각화
- 진행 중 이슈와 완료 기억의 상태 전환
- 원문 보존, 관련 이력 탐색과 2-hop 근거 수집
- 대표 시나리오 세 가지의 재현 가능한 데모
- AI 분석, 테스트 케이스, 파생 기억과 의미 색인의 POC 동작
- 동일 버전과 조건에서의 성능·비용·사용성 비교 실험

합성 데이터는 실제 업무 효과, 운영 안정성, 보안 적합성 또는 전사 규모 성능을 입증하지 않는다.

## 정량값의 해석 원칙

다음은 저장소나 실행으로 직접 확인할 수 있는 **구현 사실**이다.

- 기본 이슈 294건과 그 구성
- 테스트 케이스 수와 테스트 통과 여부
- 특정 버전에서 측정한 응답 시간, 요청 수, 토큰 수와 API 비용

시간 절감률, 정확도, 누락률, 업무 품질과 사용자 만족도는 **측정 결과**다. 이러한 값을 공개할 때는 최소한 다음 정보를 함께 기록한다.

1. 코드·데이터 버전 또는 커밋
2. 측정 일시와 실행 환경
3. 참가자 수, 과제 수, 반복 횟수와 제외 기준
4. 비교 기준과 동일 조건을 유지한 방법
5. 지표 정의, 원시값, 집계 방법과 단위
6. 합성 데이터 사용 사실, 오차와 일반화 한계

통제형 POC에서 관측한 수치를 실제 운영 실적이라고 표현하지 않는다. 전사 확대 예상치는 POC 실측값과 분리하고, 인원·빈도·단가 등 가정과 계산식을 공개한다.

## 재현성과 권리

재현 시에는 `README.md`의 실행·검증 절차와 해당 시점의 잠금 파일을 사용한다. 외부 모델의 응답은 모델 버전, 제공자 라우팅, 네트워크 상태와 확률적 생성 때문에 완전히 같지 않을 수 있다. 원문 기반 검색과 자동 테스트는 외부 AI 호출 결과와 구분해 기록한다.

현재 저장소에는 `LICENSE`가 없다. 이는 작성 코드와 데이터의 권리 귀속, 고용 관계에서의 권리, 사용한 제3자 구성요소와 참고 자료의 조건을 확인한 뒤 라이선스를 결정하기 위해서다. 소스를 공개적으로 열람할 수 있다는 사실만으로 사용·수정·재배포 권한이 부여되는 것은 아니다. 각 의존성은 해당 프로젝트의 라이선스를 별도로 따른다.
