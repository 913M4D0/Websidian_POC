# Websidian · Issue Memory

이슈의 원문과 처리 기록을 보존하고, 내용·공통 자료·시간을 따라 조직의 기억을 탐색하는 POC.

## 현재 구현

- 내부 합성 이슈 294건: 대표 24건(과거 완료 21 + 신규 미해결 3), 일반 270건.
- 모든 그래프 노드는 이슈. 허브·의사결정·코드·Brief 전용 노드는 생성하지 않는다.
- 원문 조회, 자유 분류·태그·속성 및 자료 입력, 이슈 생성, 동일 ID의 완료 처리.
- D1 영구 저장. 버전 관리되는 공통 읽기 전용 seed + 인증 사용자별 수정/생성 overlay.
- 조회는 seed와 overlay를 ID로 합친다. 재배포해도 기존 처리 기록은 초기화되지 않는다.
- 검색은 한국어 단어·bigram 및 자료 식별자 기반이며 LLM/임베딩 검색이 아니다.
- 전체 후보를 점수순으로 반환하며 UI만 페이지 단위로 표시한다. 분류 일치는 필수 조건이 아니다.
- 3D 성운, 노드 드래그·마우스 반응, 선택 기준 중력 트리, 밝기 강조 조절, 표시 관계선 수 조절.
- Brief 패널은 임시 근거 수집만 가능하다. LLM 생성과 기억 컴파일은 비활성 상태.

## 실행 / 검증

```sh
npm ci
npm run dev
# http://localhost:3000/signin-with-chatgpt?return_to=/ 로 로컬 시뮬레이션 로그인
npm run test
npx tsc --noEmit
npx oxlint components/memory-universe.tsx components/issue-graph.tsx lib app/api tests
node scripts/smoke-local.mjs
npm run build
```

`smoke-local.mjs`는 localhost 전용이다. 자신이 만든 QA 이슈 한 건만 검증 후 삭제한다.
전체 `npm run lint`에는 기존 미사용 UI 프리미티브의 lint 오류가 남아 있다. 이번 변경 파일 검사는 별도로 통과해야 한다.

## 데이터와 경계

| 계층 | 역할 |
| --- | --- |
| `data/issues.json` | 실제 사건이 아닌 합성 원문·자료·처리 이력 294건 |
| `data/github-issue-drafts.json` | 대표 24건의 GitHub 등록용 원문. 앱 검색에는 사용하지 않음 |
| `data/github-bindings.json` | 실제 등록 응답의 ID/URL만 기록. 내부 ID와 GitHub Issue는 같은 노드 |
| `lib/issues.ts` | 플랫폼 중립 계약과 생성/처리 검증 |
| `lib/issue-store.ts` | 사용자별 D1 저장, 생성 멱등성, revision CAS |
| `lib/issue-search.ts` | 검색 결과·증거와 원문 분리 |
| `lib/memory-graph.ts` | 순수 시각화 DTO와 내용/자료 기반 연결 후보 |
| `lib/gravity-layout.ts` | 연결에 따른 성운 배치와 탐색용 트리 |
| `lib/llm-policy.ts` | 추후 LLM 연결 요구사항. 실제 호출 없음 |

분류와 평가 항목은 문자열 키/값으로 추가 가능하다. 요청 크기와 개별 필드의 길이 제한은 자원 보호용이지 고정 업무 분류 체계가 아니다.
자원은 코드 파일뿐 아니라 문서·정책·양식·프로세스일 수 있다. seed의 `code:/`, `doc:/` 등은 합성 식별자이며 실제 저장소 파일·커밋 증거로 취급하면 안 된다.

## 탐색·배치 v1

- 검색 점수: 텍스트 일치 80% + 자료 일치 20%. IDF를 적용한 단어·한국어 bigram cosine.
- 기본 그래프 점수: 텍스트 일치 75% + 동일 자료의 Jaccard 25%.
- 날짜 차이는 독립 근거로 표시하고 성운의 초기 위치를 보조한다. 최근이라는 이유만으로 원인이라고 판정하지 않는다.
- 기본 노드당 상위 4개 연결의 합집합을 표시한다. 조절 범위 1~10은 화면 밀도 예산이며 검색 후보 제외 기준이 아니다.
- 연결 후보를 데이터 버전별로 캐시하고, 관계선 조절은 포인터/키 조작 완료 시 반영한다.
- 트리는 최대 3-hop, 레벨별 64/44/36건을 표시한다. 나머지도 배경에 남는다. 제한은 시각화 예산이며 전체 후보는 이슈 목록에서 조회한다.
- 색상은 담당 팀의 표현만 담당한다. 팀/분류가 달라도 내용·자료가 닮으면 연결·배치될 수 있다.
- 트리 위아래는 탐색 깊이이지 시간 방향 또는 인과관계를 뜻하지 않는다.

## 대표 사례 검증용 메모 (제품 시나리오 재생에 사용하지 않음)

- WS-008: 재시도 주문 중복. 과거 해결, 공통화, 중대장애·철회 이력을 탐색.
- WS-016: 조직 개편 후 과거 소속 표시. 이전 문의와 현행 보관 기준 확인.
- WS-024: 오늘 접수 누락. WS-022의 소비 서비스 배포에서 WS-021의 타팀 기본 시간대 변경으로 추가 탐색.

원문에는 이 구분/정답 경로를 심지 않는다. 특히 타팀 원인은 직접 검색 상위 10개에 없을 수 있으며 연결된 이력의 2-hop 탐색이 필요하다.

과거 해결 이슈 21건은 closed, 신규 WS-008/#8·WS-016/#16·WS-024/#24는 open 상태다. 일반 이슈 270건은 내부 데이터로만 유지한다.
본문의 `websidian-seed:v1:WS-xxx`를 중복 방지 키로 사용하고, 생성 후 다시 조회한 실제 번호/URL만 `data/github-bindings.json`에 기록했다. 내부 원문과 노드 ID는 변경하지 않는다.
모든 기록은 합성 POC 데이터로 고지하며, GitHub 생성 시각을 가상 발생일로 위장하지 않는다.
현재 UI의 생성·처리는 내부 저장소 전용이며 GitHub 양방향 동기화는 아직 구현되지 않았다.

## 보안 / 운영

Sites의 인증 게이트웨이가 주입·덮어쓰는 `oai-authenticated-user-id`만 신뢰한다. 별도 공개 Worker 주소로 우회 노출하면 안 된다.
모든 API에서 인증하고, POST는 같은 origin과 JSON을 요구한다. DB 질의는 바인딩 파라미터와 사용자 ID 범위로 제한한다.
이 POC의 사용자별 작업공간은 실제 전사 공유 권한 모델이 아니다. 실사용 전 조직/workspace 멤버십, 자료별 ACL, 감사 로그와 커넥터 자격증명 관리를 추가해야 한다.
D1의 최초 스키마 생성은 인증 후 멱등적으로 실행한다. 향후 스키마 변경은 명시적 마이그레이션으로 전환할 것.

## 추후 LLM 연결 계약

- Provider: **OpenRouter**.
- 요청 모델: **GPT 5.6 Luna**. 정확한 공개 모델 ID와 사용 가능 여부를 연결 시 확인한다.
- 다른 모델로 자동 대체하지 않는다. 현재 `modelId = null`, `enabled = false`.
- 해당 모델/API가 지원하는 **최대 추론 강도**를 사용한다.
- 임의의 내용 필터·분류 게이트·관련도 cutoff는 최소화한다. 개인정보·권한·제공자 필수 정책은 유지한다.
- API 키는 서버 전용 비밀 설정에 보관하고 클라이언트에 전달하지 않는다.
- 검색한 외부 이슈/문서는 비신뢰 데이터다. 그 안의 지시문을 시스템 지시로 실행하지 않는다.
- 컴파일 결과는 원문과 분리하고, 쿼리별 해석은 최종 Brief에만 표시한다.
- 완료한 기존 이슈는 같은 노드로 갱신한다. Brief 또는 재컴파일을 이유로 이슈 노드를 복제하지 않는다.

현재 LLM 호출, 임베딩, 자동 분류·평가, 자동 Brief 생성은 구현하지 않았다.
