# Websidian POC 검색·경로 채점 기준

## 평가 단위

각 기준 이슈마다 완료 기록 7건을 관련 문서로 둡니다. 관련성 등급은 `ground-truth.json`에 있으며 1점 이상을 Recall·MRR의 relevant로 계산합니다. 대표 24건 중 다른 시나리오의 기록과 배경 270건은 해당 과제에서는 비관련 기록입니다.

## 관련성 등급

| 등급 | 판정                                                                    |
| ---: | ----------------------------------------------------------------------- |
|    3 | 핵심 판단, 핵심 위험 또는 가장 중요한 조사 경로를 직접 뒷받침합니다.    |
|    2 | 대안 원인, 운영 경계, 적용 방식 또는 안전 조건을 유의미하게 보강합니다. |
|    1 | 핵심 답은 아니지만 배제 여부를 확인할 가치가 있는 보조 기록입니다.      |
|    0 | 해당 시나리오의 판단에 사용할 구체적 원문·자료 연결이 없습니다.         |

유사한 단어만 있다는 이유로 관련 등급을 주지 않습니다. 반대로 관련 기록이 곧 원인이라는 의미도 아닙니다.

## 순위 지표

### Recall@K

`Top-K 안의 relevant 고유 ID 수 ÷ relevant 전체 ID 수`

각 시나리오의 relevant는 7건입니다. K보다 relevant가 많으므로 Recall@5의 이론적 최대값은 `5/7`입니다.

### MRR

`1 ÷ 첫 relevant 기록의 순위`

세 과제 모두 첫 relevant를 찾는 데는 쉬울 수 있으므로 MRR 단독으로 제품 우위를 주장하지 않습니다.

### nDCG@K

등급 1~3을 gain으로 사용해 상위에 핵심 기록이 배치되는 정도를 측정합니다. DCG gain은 `2^grade - 1`, discount는 `log2(rank + 1)`입니다.

### Distractor false-positive rate@K

`Top-K 슬롯 중 relevant가 아닌 ID 수 ÷ 실제 반환된 Top-K 슬롯 수`

이 값은 전체 음성 문서 수를 분모로 하는 전통적 FPR가 아니라 검색 결과 안의 오탐 비율입니다. 보고서에는 이 정의를 함께 표기합니다.

### Background-270 rate@K

`Top-K 슬롯 중 WS-025..WS-294 ID 수 ÷ 실제 반환된 Top-K 슬롯 수`

다른 대표 시나리오의 이슈로 인한 오탐과 일반 배경 노드로 인한 오탐을 구분합니다.

## 생산성 대리지표

### 첫 grade-3 근거까지 확인 문서 수

첫 번째 관련성 3등급 기록이 나타나는 순위입니다. 값이 작을수록 핵심 근거를 일찍 접하지만, 실제로 그 문서를 읽고 이해한 시간은 측정하지 않습니다.

### 모든 grade-3 근거까지 필요한 문서 수

모든 3등급 기록을 회수한 경우 그중 가장 뒤의 순위입니다. 하나라도 결과에서 미회수되면 빈 값으로 두고 `missing_grade3_ids`에 누락 ID를 기록합니다.

### Top-10 유효근거 밀도

`Top-10 안의 grade 1~3 기록 수 ÷ 실제 반환된 Top-10 슬롯 수`

### Grade-3 coverage@10

`Top-10 안의 grade-3 고유 ID 수 ÷ grade-3 전체 ID 수`

### LLM 문맥 선별 비율

- 건수: `buildIssueInsightContext가 선택한 관련 완료 이력 수 ÷ 완료 이력 251건`
- 문자수: `실제 선택 컨텍스트의 JSON 문자수 ÷ 같은 발췌 규칙으로 완료 이력 전체를 투영한 비교 컨텍스트의 JSON 문자수`

전체 컨텍스트는 비용이 발생하는 모델 호출을 하지 않습니다. 문자수는 토큰수와 다르므로 토큰 또는 비용 절감률로 바꾸어 말하지 않습니다.

이 네 값은 검색 결과를 사람이 순서대로 확인한다는 가정 아래의 **순위 기반 생산성 proxy**입니다. 실제 시간 절감, 생산성 향상, 인력 절감 또는 비용 절감으로 표현하지 않습니다.

## 경로 지표

### Direct path recall

`expectedDirectIssueIds 중 buildHistory가 depth 1로 반환한 ID 수 ÷ 기대 직접 ID 수`

### 2-hop target recall

`expectedTwoHopPaths의 target 중 buildHistory가 depth 2로 반환한 ID 수 ÷ 기대 target 수`

### 2-hop path recall

`depth 2 target과 viaIssueId가 모두 허용 경로와 일치한 수 ÷ 기대 경로 수`

target을 찾았지만 다른 중간 기록을 제시하면 target recall에는 포함하고 엄격한 path recall에는 포함하지 않습니다. 이는 결과 누락과 설명 경로 품질을 분리하기 위한 것입니다.

## 실행시간

- 각 과제·방법을 5회 준비 실행한 뒤 설정된 횟수만큼 반복합니다.
- p50과 p95 밀리초를 기록합니다.
- 동일 프로세스·동일 데이터·동일 장비 안의 상대 비교에만 사용합니다.
- 데이터 로딩, JSON 파일 기록, 화면 렌더링 시간은 포함하지 않습니다.

## 시나리오별 사람 채점 보조 기준

사람 참여 실험에서는 검색 지표와 별도로 다음을 각 0~2점으로 블라인드 채점합니다.

| 항목           | 0점                   | 1점              | 2점                                        |
| -------------- | --------------------- | ---------------- | ------------------------------------------ |
| 근거 발견      | 핵심 등급 3 기록 없음 | 일부 발견        | 핵심 기록과 연결 이유를 모두 제시          |
| 사실·추정 구분 | 원인을 확정           | 표현이 혼재      | 조사 후보와 확인된 사실을 명확히 구분      |
| 안전 조건      | 중대한 조건 누락      | 일부 언급        | 승인·원문보존·정책·회귀 조건을 적절히 반영 |
| 다음 행동      | 근거 없는 수정        | 추가 확인만 제시 | 검증 순서와 수정 여부 판단 기준을 제시     |
| 테스트 범위    | 정상 경로만 제시      | 위험 조건 일부   | 대표 과거 실패와 대안 원인을 모두 포함     |

이 점수는 자동 검색 지표와 합산하지 않습니다. 두 평가자는 도구 조건과 제품 순위를 모른 채 독립 채점하고 불일치는 합의 기록으로 남깁니다.

## 금지되는 해석

- 합성 벤치마크 시간을 실제 현업 절감시간으로 표현하지 않습니다.
- 검색 점수, 관계선, hop을 원인 확률이나 인과 증명으로 해석하지 않습니다.
- 대표 24건에 맞춘 결과를 다른 업무·계열사 전체에 일반화하지 않습니다.
- 평가 결과를 확인한 뒤 이유 없이 qrels를 고쳐 점수를 높이지 않습니다.
